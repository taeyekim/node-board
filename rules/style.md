# Style Rules

## 기본 원칙

- 기존 구조와 스타일을 우선 존중한다.
- 불필요한 리팩토링을 하지 않는다.
- 요청한 문제와 직접 관련 없는 코드는 수정하지 않는다.
- 초보자가 읽을 수 있는 단순한 구조를 우선한다.

## Monorepo 구조

예상 구조:

```text
apps/web
apps/server
```

프론트엔드와 백엔드는 역할을 분리한다.

## React

- 컴포넌트는 작고 읽기 쉽게 유지한다.
- API 호출 로직은 반복되면 별도 함수로 분리한다.
- 상태 관리는 처음에는 React 기본 상태로 시작한다.
- 전역 상태 관리 라이브러리는 사용자 승인 없이 추가하지 않는다.

## Express

- API 라우트는 기능별로 정리한다.
- 복잡한 파일 읽기/쓰기 로직은 라우트에서 분리한다.
- 에러 처리는 숨기지 않는다.
- 임시 로그는 남기지 않는다.

## Tailwind CSS

- 공식 문서와 무료 예시를 기준으로 사용한다.
- 과도하게 복잡한 클래스 조합은 피한다.
- 반응형 기본 동작을 확인한다.

## 리팩토링 기준

리팩토링은 다음 경우에만 제안한다.

- 중복이 기능 추가를 방해한다.
- 검증이 어려운 구조다.
- 기존 코드가 오류 가능성을 높인다.

리팩토링은 기능 검증 전에는 진행하지 않는다.
